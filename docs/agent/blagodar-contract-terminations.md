# Расторжения договоров: выдача для сводки владельца

**Для кого:** разработчик CRM «БлагоДар».
**От кого:** сайт колл-центра (callcenter-crm), сводка владельца «Потолки».
**Дата:** 27.11.2026.

## Зачем

Владелец попросил показывать в CRM потолков расторжения по договорам.

Решение владельца:
- брать расторжения **автоматически из 1С через CRM «БлагоДар»**;
- руками никто ничего не вносит.

Наша сторона уже готова: блок «Расторжения договоров» в сводке «Потолки». Пока выдачи нет, он пишет «появятся, когда будет подключена их выдача». Нужна только выдача с вашей стороны.

## Что считать расторжением

Так сейчас делают в 1С:
- у заказов договора ставят **«Отменен»** (`ВариантЗавершения`);
- **причину ставят «Расторжение»**.

Расторгнутый договор:
- договор с номером в начале названия, как в «Прибыли договоров»;
- у него **все** заказы (проведённые, кроме расчётов, разбитых на другие заказы) отменены;
- у отмены стоит причина «Расторжение».

Где в 1С эта причина, мы не знаем. Найдите её в метаданных `Документ.ЗаказПокупателя`: скорее всего это реквизит причины отмены. Если сотрудники пишут её в комментарий, ищите слово «растор» в `Комментарий`.

**Отменён целиком, но причина не «Расторжение»** (дубль, перезаключили, ошибка):
- в список не входит;
- считается одним числом `unmarked`. По нему владелец увидит, если причину забывают ставить.

**Частичная отмена** (один заказ из нескольких, например свет) — это не расторжение. Сейчас её не считаем.

## Дата расторжения

Период выбирается по дню расторжения. В 1С этой даты, скорее всего, нет. Выберите лучшее из доступного, по порядку:

1. Дата документа возврата денег заказчику по договору, если он есть.
2. Версии объектов 1С, если в базе включено версионирование.
3. День, когда CRM впервые увидела договор отменённым с причиной «Расторжение». Срезы заказов приходят раз в 20 минут, так что для новых расторжений это точный день.
4. Для истории до запуска выдачи — день последнего заказа договора, с `dateKnown: false`.

## Запрос

```http
GET {API}/api/reports/contract-terminations/summary?from=2026-11-01&to=2026-11-30
Authorization: Bearer <служебный ключ>
Accept: application/json
```

- `from` и `to` — дни включительно, `Y-m-d`.
- Ключ отдельный, как у прибыли и незаключёнок. Например `TERMINATIONS_SUMMARY_TOKEN` и `requireServiceToken`.
- У нас ключ лежит только в `.env` сервера (`BLAGODAR_TERMINATIONS_TOKEN`). Адрес берём тот же, что у прибыли договоров (`https://blagodar-crm.ru`).
- `401` — нет ключа или он неверный, `403` — выдача выключена. Мы показываем это владельцу словами.

## Ответ `200`

```jsonc
{
  "updated": { "onec": "2026-11-27T10:20:00+04:00" },  // когда пришёл последний срез заказов из 1С
  "stale": [],                                          // предупреждения словами: «база Салихов не отвечает с 25.11»
  "period": { "from": "2026-11-01", "to": "2026-11-30" },
  "totals": {
    "contracts": 4,            // расторгнуто договоров за период
    "amount": "512000.00",     // их сумма: заказы договора до отмены
    "paid": "150000.00",       // заказчик успел заплатить по договору; не знаете — null
    "refunded": "90000.00",    // вернули заказчику; не знаете — null
    "kept": "60000.00",        // осталось у нас = paid − refunded (затраты по п. 8.2 договора); не знаете — null
    "unmarked": 2              // отменены целиком, но причина не «Расторжение»; в список и итоги не входят
  },
  "by_measurer": [             // кто замерял расторгнутые договоры (как в «Прибыли договоров»)
    { "measurer": "Костюнин Федор", "contracts": 2, "amount": "300000.00" }
  ],
  "items": [                   // все расторжения периода, свежие первыми
    {
      "base": "unf_18",
      "label": "Закирова 2026",        // название базы — как в остальных отчётах
      "number": "2296",                // номер договора
      "contractDate": "2026-09-29",    // день договора
      "terminatedAt": "2026-11-20",    // день расторжения (см. «Дата расторжения»)
      "dateKnown": true,               // false — день примерный (история до запуска)
      "amount": "185000.00",
      "paid": "50000.00",              // может быть null
      "refunded": "30000.00",          // может быть null
      "reason": "Расторжение",         // причина из 1С, как написана
      "comment": "…",                  // комментарий заказа 1С, до 200 знаков; может не быть
      "measurer": "Костюнин Федор",    // может быть null
      "url": "https://blagodar-crm.ru/…"  // карточка договора или сделки у вас; может не быть
    }
  ],
  "url": "https://blagodar-crm.ru/reports/…"  // полный отчёт у вас, если есть; может не быть
}
```

- Деньги — строки с точкой, как в прибыли договоров.
- Заказчиков и адресов в выдаче нет: это по вашему правилу для сводок. Владелец откроет договор по `url`.
- Нечего показать за период — `items: []` и нули в `totals`, не `404`.

## Что мы покажем

В сводке «Потолки», под «Прибылью договоров»:
- четыре плитки: «Расторгнуто», «На сумму», «Вернули заказчикам», «Осталось у нас»;
- строка про `unmarked`, если их больше нуля;
- таблица по замерщикам;
- список договоров: база, номер, от какого числа, когда расторгнут, сумма, оплачено, вернули, причина и комментарий, ссылка.

В «Прибыли договоров» отменённые заказы у вас и так не считаются, поэтому расторжения идут отдельным блоком и в прибыль не вычитаются.

Ответ мы держим в кэше 10 минут, сбой — 1 минуту. Запрос — по одному на открытие сводки.

## Как проверить вместе

1. Вы даёте ключ. Мы вносим его в `.env` нашего сервера и делаем `config:cache`.
2. Открываем сводку «Потолки» за прошлый месяц. Число расторжений должно совпасть с числом договоров в 1С, у которых все заказы «Отменен» с причиной «Расторжение».
