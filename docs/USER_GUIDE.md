## Быстрый старт (за 5 минут)

**День 1 — наполнить склад:**
1. Войдите в систему (см. [Вход в систему](#вход-в-систему-и-роли)).
2. **Склад → Импорт пачкой** — вставьте список кроссовок в поле, укажите «кол-во по 1» и нажмите **Импортировать**.
3. Пробегитесь по карточкам — при желании измените категорию/пол/сезон (по умолчанию система определит их сама по названию).
4. Загрузите фото товаров кликом по большой квадратной плашке слева в карточке.

**День 2 — принять первую живую партию:**
1. Создайте закупку в **Закупки** («+ Закупка»).
2. Заполните бренд/модель/размер/кол-во/цену/поставщика.
3. Перетащите карточку в стадию **«Получено / На складе»** — товар автоматически появится на складе с себестоимостью.

**Первая продажа:**
1. Создайте сделку в **Продажи** («+ Сделка»).
2. В карточке сделки в блоке **«Склад · что продаём»** выберите товар и укажите кол-во — сумма подставится сама.
3. Перетащите сделку в **«Бронь/Счёт»** — размер зарезервируется. Затем в **«Продано»** — спишется со склада, руководителю прилетит уведомление.
4. При желании нажмите **🖨️ Печать чека**.

## Вход в систему и роли

**Адрес:** `https://crm.callcenter-crm.ru`

**Учётные записи отдела** (пароли выдаёт руководитель):
- **Руководитель** — логин `krossovki`. Роль `sneaker_head`. Может всё: заводить пользователей, редактировать цены, удалять позиции.
- **Оператор** — логин `krossovki_op`. Роль `sneaker_operator`. Работает с приёмкой, продажами, приходом-расходом. **Не может** редактировать цены и удалять позиции.

> **Смена пароля:** руководитель → раздел **Пользователи** → в строке нужного сотрудника введите новый пароль → **Пароль**.

Отдел кроссовок работает **в изолированном пространстве**: сотрудники другой команды (натяжные потолки) не видят ваш склад и продажи, вы не видите их. Всё разделено по «аккаунтам».

## Навигация: разделы отдела

В верхней панели видны только пункты вашего отдела:

- **Закупки** — канбан закупок (лид → заказ → путь → склад).
- **Склад** — все товары с фото, ценами, размерами. Бейдж на «Склад» показывает, сколько позиций заканчивается.
- **Приёмка** — окно со сканером для быстрого прихода.
- **Продажи** — канбан сделок (лид → бронь → продано).
- **Список** — таблица всех сделок с фильтрами.
- **Дела** — задачи (созвониться, напомнить, оформить).
- **Завершённые** — архив сделок.
- **Отчёты** — сводный дашборд по кроссовкам.
- **Пользователи** (только руководитель) — управление сотрудниками.

Справа в панели:
- Колокольчик — уведомления (продажи, низкий остаток).
- Тема — светлая / закат / лес / тёмная.
- Выйти.

## Склад

Открыть: **Склад** в верхней панели.

Наверху страницы — сводка:
- Всего товаров (уникальных моделей).
- Пар на складе (сумма).
- Доступно (без учёта резерва).
- Стоимость по ценам продажи.

Ниже — тулбар: поиск, фильтр «Заканчивается», ссылки на **Экспорт CSV**, **Импорт пачкой**, **📊 Аналитика**.

Ещё ниже — второй ряд чипов: **Категория · Пол · Сезон**. Один клик — фильтруется, повторный — снимается. Можно комбинировать (например, «Спортивные + Мужские + Демисезон»).

### Карточка товара

Каждый товар — отдельная карточка с:

- **Большое фото 120×120** слева (или буквенный аватар бренда, если фото нет).
- **Название** — редактируемое (карандаш ✎ рядом).
- **Артикул** и мини-штрих-код (Code128) + кнопка **🖨️ Этикетка** для печати ценника.
- Три `<select>`: **Категория**, **Пол**, **Сезон** — меняются мгновенно.
- Сводка: пар / доступно / резерв / стоимость.
- **Полоска миниатюр** дополнительных фото + «+».
- **Плитки размеров** — размер, крупная цифра остатка (зелёная/жёлтая/красная), кнопки **−/+**.
- Клик по плитке размера → компактное окошко с точным вводом кол-ва, цены (только руководитель), минимального остатка (только руководитель), удалением (только руководитель).
- **+ размер** — плитка в конце строки, добавляет новый размер без пересоздания товара.

### Добавить товар вручную

1. В правом нижнем углу — **кнопка +** (плавающая).
2. В форме укажите: бренд, модель, размер, кол-во, цену продажи, минимальный остаток.
3. **Создать**.

Если такая модель уже есть на складе, а размер новый — добавится как новый размер к существующей карточке.

### Массовый импорт из текста

Удобно, когда поставщик прислал прайс списком.

1. **Склад → Импорт пачкой**.
2. Вставьте список в поле. Формат каждой строки:
    ```
    БРЕНД МОДЕЛЬ ... - размер, размер, размер
    ```
    Примеры (реально из практики):
    ```
    NIKE DUNK LOW PINK VELVET GS - рр 37
    PUMA LAMELO BALL LAFRANCÉ AMOUR SLIME- рр 42,43
    NEW BALANCE 237 SOUR GRAPE LEMON WOMEN'S-36,36.5
    NIKE BLAZER LOW OFF WHITE BLACK ELECTRO GREEN-41,41.5,42,43.5
    ```
3. Укажите **кол-во каждой пары** (обычно 1).
4. **Импортировать**.

Правила парсера:
- Первое слово — бренд (`NIKE`, `PUMA`, `ADIDAS`, `KAPPA`, `LACOSTE`, …).
- Двусоставный бренд **`NEW BALANCE`** распознаётся автоматически.
- До первого «-» — модель.
- После «-» — размеры через запятую или пробел (можно с «рр»).
- Если позиция уже есть — количество прибавится (не создаётся дубликат).

**Блочный формат** (типичный список пополнения от поставщика) — тоже поддерживается тем же полем. Блоки разделяются пустой строкой, внутри блока три строки:

```
New balance 9060
42,43(2)
U9060ORA
```

- 1-я строка — название (бренд + модель; «W Nike …» тоже понимается).
- 2-я строка — размеры через запятую; **в скобках — количество пар** этого размера (без скобок = 1). Склейки без запятой («38(2)37.5») тоже понимаются.
- 3-я строка — артикул (код расцветки): каждая расцветка станет отдельной карточкой товара.

### Импорт из Excel (.xlsx)

На той же странице **Импорт пачкой** есть загрузка Excel-файла. Формат листа (первая строка — заголовки, пропускается):

| Название | Размер | Кол-во | Артикул |
|---|---|---|---|
| Nike Dunk low retro | 44.5 | 2 | DV0833 800 |
| New Balance 9060 | 42 | 1 | Y9060-BPM |

- **Название** — бренд + модель одним текстом (бренд определяется по первому слову).
- **Артикул** (код расцветки) необязателен, но важен: **каждая расцветка станет отдельной карточкой товара** со своим фото и артикулом (артикул добавляется к названию модели).
- **Два режима:**
  - **«Файл — полный срез остатков»** (по умолчанию) — количества устанавливаются как в файле. Можно смело загружать один и тот же дополняемый файл повторно — ничего не задвоится.
  - **«Прибавить»** — количества прибавляются к текущим (для загрузки новой поставки отдельным файлом).
- Позиции, которых нет в файле (в т.ч. другие бренды), не изменяются.

### Фото товара (галерея)

- **Главное фото:** клик по большой плашке 120×120 → выбор файла (jpg/png/webp, до 5 МБ).
- **Заменить главное:** клик по фото ещё раз или удалить крестиком.
- **Дополнительные:** нажмите **+** в полоске миниатюр под шапкой карточки. Можно добавить сколько угодно.
- **Удалить конкретное фото:** наведите мышь на миниатюру → нажмите красный **×**.

### Артикул, штрих-код, этикетка

- **Артикул** формата `K-XXXXX` (`K-00001`, `K-00002`, …) — генерируется автоматически при появлении товара. Уникален в вашем отделе.
- **Мини-штрих-код** (Code128) отображается прямо на карточке.
- **🖨️ Этикетка** — открывает страницу печати с большим штрих-кодом и артикулом. Кнопка «Печать» открывает системный диалог принтера.

**Что делать с этикеткой:** наклеить на коробку. При приёмке или продаже — отсканировать (см. [Приёмка ТСД](#приёмка-со-сканером-тсд)).

Артикул можно перебить вручную (карандаш ✎), но в 99% случаев автогенерации хватает.

### Категория, пол, сезон

Три оси разметки для аналитики и фильтрации:

- **Категория:** 🏃 Спортивные / 👟 Повседневные / 💎 Премиум / ❄️ Зимние / 🧒 Детские.
- **Пол:** 👨 Мужские / 👩 Женские / ⚦ Унисекс / 🧒 Детские.
- **Сезон:** ☀️ Лето / ❄️ Зима / 🍂 Демисезон.

Система угадывает эти значения автоматически по названию:
- `Air Max / Dunk / Blazer / Samba` → **спорт**.
- `Suede / Classic / Originals / Lifestyle` → **повседневные**.
- `Off-White / Jordan / Yeezy` → **премиум**.
- `Gore-Tex / Timberland / зимн` → **зима**.
- `WOMEN'S / WMNS` → **женские**; `GS / TD / KIDS` → **детские**; иначе — **унисекс**.
- `SANDAL / SLIDE / летн` → **лето**; иначе — **демисезон**.

Если угадала неправильно — просто выберите верное значение в `<select>` карточки, сохранится мгновенно.

### Цены: закуп и продажа (только руководитель)

У каждого товара руководитель задаёт две цены — **за сколько закупаем** (себестоимость) и **за сколько обычно продаём**:

1. На карточке товара откройте **⚙️ Управление товаром** → строка **«Цены»**.
2. Введите закуп и/или продажу → **«Применить ко всем размерам»** — цены проставятся сразу на всю расцветку. Рядом система покажет **наценку %**.
3. Если у отдельного размера цена другая — откройте плитку этого размера и поправьте «Закупка ₽» / «Продажа ₽» точечно.

Зачем это нужно:
- **Цена продажи** автоматически подставляется на экране «💵 Продажа» (продавцу не нужно её помнить).
- **Закупочная цена** участвует в расчёте **прибыли** в Отчётах и Аналитике (без неё прибыль не считается).
- Закуп также обновляется автоматически при приёмке через канбан Закупок (средневзвешенно).

Оператор цен не видит и менять их не может.

### Управление размерами и остатками

- **Быстрые ±1:** кнопки на плитке размера.
- **Точный остаток:** клик по плитке → введите число → OK.
- **Изменить цену продажи** (только руководитель): клик по плитке → цена ₽ → OK.
- **Минимальный остаток** (только руководитель): при снижении «доступно» ниже него товар помечается как «заканчивается» (жёлтая рамка + чип и бейдж в навбаре).
- **Удалить размер** (только руководитель): клик по плитке → «Удалить».
- **Добавить новый размер:** плитка **+ размер** в конце строки товара.

### Фильтры и поиск

- **Поиск сверху:** ищет по бренду, модели и размеру.
- **Чип «Заканчивается»:** только позиции ниже минимального остатка.
- **Категория/Пол/Сезон:** клик — включить, повторный — выключить. Комбинируются.

## Приёмка со сканером (ТСД)

Открыть: **Приёмка** в верхней панели.

Большое поле с автофокусом. ТСД или USB-сканер вводит код и сразу «нажимает Enter» — обработка происходит без единого клика мыши.

**Два режима — переключаются вкладками сверху:**

**1. 📦 Артикул `K-XXXXX`.**
- Сканируете штрих-код с этикетки товара.
- Система находит модель по артикулу и **прибавляет** указанное количество (по умолчанию 1) к остатку первого размера этой модели.
- В блоке «Последний код» появляется: `✓ Принято на склад: NIKE Dunk Low · р. 42 × +1`.

**2. 🏷️ Код маркировки (Честный знак).**
- Сканируете DataMatrix-код с коробки.
- Код привязывается к **последней принятой позиции** (той, на которую только что делали приход в режиме «Артикул»).
- Статус: `in_stock` (в обороте).
- Дубликаты система не принимает.

**Сценарий полной приёмки коробки:**
1. Переключитесь в **📦 Артикул**, отсканируйте штрих-код с коробки → приход.
2. Переключитесь в **🏷️ Код маркировки**, отсканируйте DataMatrix с этикетки «Честного знака» → код привязался.
3. Повторите со следующей коробкой.

Внизу — список **«Последние приходы»** для контроля.

## Канбан закупок

Открыть: **Закупки** в верхней панели.

Отдельный канбан со своими стадиями:

- **Надо купить** — черновики / идеи.
- **Заказано** — заявка отправлена поставщику.
- **Оплачено** — деньги ушли.
- **В пути** — товар в дороге.
- **Получено / На складе** ✅ **при переходе сюда — товар автоматически приходуется на склад** (в вашей номенклатуре появляются позиции с себестоимостью).
- **Готово к продаже** — финальная стадия (уже на витрине).

**Создать закупку:**
1. **+ Закупка** сверху.
2. Название, бренд, модель, размер, кол-во, поставщик, закупочная цена, ожидаемая цена продажи, артикул/ссылка на заказ, ответственный, заметки.
3. Создать.

**Что происходит при перетаскивании в «Получено / На складе»:**
- Позиция `бренд + модель + размер` создаётся (или обновляется).
- Кол-во прибавляется, себестоимость обновляется как **средневзвешенная**.
- Пишется запись в «Последние движения» (тип «Приход»).

При обратном перетаскивании — приход откатывается.

**Если правите количество уже оприходованной закупки** — система автоматически досинхронизирует остаток: докупили 2 → +2, уменьшили с 5 до 3 → −2.

**Закрыть/архив** — на карточке закупки внизу. Уходит из канбана; остаток на складе остаётся.

## Быстрая продажа (💵 Продажа)

**Основной способ оформить продажу** — зелёная кнопка **💵 Продажа** в меню. Один экран:

1. Наберите модель в поиске (или пикните сканером по штрих-коду коробки).
2. Нажмите на квадратик нужного размера (видно, сколько пар в наличии).
3. В нижней панели проверьте кол-во и цену (подставляется сама), при желании укажите источник и клиента.
4. Нажмите **«✅ Продать»**.

Система автоматически: создаст сделку в стадии «Продано», спишет пару со склада, уведомит руководителя и предложит **напечатать чек**. Если размер закончился — покажет предупреждение.

Канбан продаж (ниже) нужен для «длинных» сделок: переписка с клиентом, бронь, счёт. Для продажи «здесь и сейчас» всегда используйте 💵 Продажу.

## Канбан продаж (сделки)

Открыть: **Продажи** в верхней панели.

Стадии:
- **Новый лид**
- **Связались / В работе**
- **Подобрали модель**
- **Бронь / Счёт** — товар зарезервируется на складе.
- **Продано** ✅ финальная — товар списывается, руководитель получает уведомление, коды маркировки помечаются `sold`.
- **Отказ** — сделка не состоялась.

**Создать сделку:**
1. **+ Сделка** сверху.
2. Название, ответственный, сумма, категория «Кроссовки», контакт клиента.
3. Создать.

В карточке сделки:
- Основные данные.
- Задачи / Дела.
- **Склад · что продаём** (важнейший блок для кроссовок — см. ниже).
- Чаты (VK/Telegram/Avito).
- Лента истории.

### Резерв и продажа

Блок **«Склад · что продаём»** внутри карточки:

1. **Товар со склада** — выпадающий список с указанием доступности «(доступно: 3 / 5, 12 000 ₽)». Выберите товар.
2. **Кол-во пар** — по умолчанию 1.
3. **Источник** — Avito / Instagram / Telegram / Сайт / Сарафан / Другое.
4. **Сохранить**.

Сумма сделки автоматически подставится = цена × кол-во (если сумма ещё не задана).

**Дальше — просто двигайте сделку по стадиям:**
- Стадия **«Бронь / Счёт»** → пары **резервируются** на складе (не списываются, но «доступно» уменьшается).
- Стадия **«Продано»** → пары **списываются**, себестоимость запоминается на сделке, руководитель получает пуш «Новая продажа кроссовок».
- Возврат сделки на предыдущую стадию → всё откатывается.

Если на складе меньше, чем продаёте — система предупредит в сообщении статуса, но не заблокирует (иногда бывает нужно продать «в минус»).

### Коды маркировки («Честный знак»)

Прямо в блоке «Склад · что продаём» — поле **«Коды маркировки»**:
- Вставьте / отсканируйте DataMatrix-коды (**по одному в строке**).
- Нажмите **Добавить коды**.
- Список появляется ниже с бейджем статуса (`in_stock` / `sold` / `returned`).

При переводе сделки в **«Продано»** статус автоматически меняется на `sold` (готово к отправке в ГИС МТ, когда подключим боевой API «Честного знака»).

При возврате / переоткрытии — коды возвращаются в `in_stock`.

### Печать чека

Кнопка **🖨️ Печать чека** появляется в блоке «Склад · что продаём» после того, как сделка перешла в «Продано».

- Открывается страница узкого формата (78 мм — под термо-принтер).
- Шапка: название компании, ИНН, адрес.
- Тело: товар, количество × цена = ИТОГО.
- Кнопка **🖨️ Распечатать** внутри окна.

> **Важно:** это **товарный** чек. Он не заменяет фискальный (которого требует 54-ФЗ). Мы подготовили разъём под ККТ / ОФД — см. [Будущие интеграции](#будущие-интеграции-честный-знак-онлайн-касса).

### Возврат

Если клиент вернул товар (после «Продано»):
1. В карточке сделки — кнопка **«Оформить возврат»** в блоке склада.
2. Пары возвращаются на склад, коды маркировки → `in_stock`, сделка помечается как возвращённая.
3. В отчёте появится в разделе «Возвраты за период».

## Аналитика склада

Открыть: **Склад → 📊 Аналитика** в тулбаре.

Более глубокий срез, чем отчёт:

1. **🌤 Сезонность продаж — 12 месяцев** — столбики по месяцам, разбитые на топ-5 брендов разными цветами. Видно, какие месяцы горячие, какой бренд когда лидирует.
2. **📈 Закупки vs продажи по месяцам** — зелёные (закупили) и красные (продали) столбики бок о бок. Растёт склад или сокращается.
3. **🚀 Быстро оборачиваются** — топ моделей по продажам за 90 дней, колонка «Дней до нуля». Красные — критично (≤14 дней).
4. **💤 Мёртвый склад** — есть остаток, но 0 продаж за 90+ дней. Деньги замороженные.
5. **⏳ Скоро закончатся** — при текущей скорости хватит на ≤ 21 день. «Пора заказывать».
6. **🧩 Структура склада и продаж** — три колонки (категории / пол / сезон) со сравнением «на складе vs продано за 12 мес». Видны перекосы («женских много на складе, а покупают мужские»).
7. **🎯 ABC-анализ** — модели, дающие 80% прибыли (A), следующие 15% (B), хвост 5% (C). Стратегия: A — всегда в наличии; B — держим умеренно; C — распродавать.
8. **👟 Размеры: продано vs остаток** — какие размеры ходовые, какие лежат. По оси X — все размеры от малых к большим.
9. **🏷️ Топ брендов** — сколько какого бренда на складе (в парах и деньгах) и продано за 12 мес.

Все графики строятся из уже собираемых данных — ручного ввода не требуют.

## Будущие интеграции: Честный знак, онлайн-касса

Разъёмы в коде уже подготовлены, но реальная интеграция требует внешних договоров.

**Честный знак (маркировка обуви):**
- Нужна регистрация в ГИС МТ (`gismt.crpt.ru`), электронная подпись УКЭП (~5 000 ₽/год), договор с оператором СУЗ (СБИС/Такском, от 10–30 к/год).
- Что уже готово в CRM: приём кодов при закупке, привязка к сделке, автоматический перевод в `sold` при переходе в «Продано», возврат в `in_stock` при отмене.
- Что добавим по факту получения ключей: автоматическая отправка «ввод в оборот» / «розничная продажа» в ГИС МТ.

**Онлайн-касса (54-ФЗ):**
- Нужны: юрлицо/ИП, договор с ОФД (Такском / Первый ОФД / Платформа ОФД), ККТ (Атол / Штрих-М / Эвотор) или облачная касса (Атол Онлайн, Модуль-касса).
- Что уже готово: HTML-чек с товаром и суммой, готовый шаблон для замены на реальный фискальный документ.
- Что добавим: `POST` в API кассы вместо HTML-чека, реквизиты чека сохраняются в сделке.

Скажите руководителю сообщить, когда получите ключи — интеграция настраивается быстро (полдня).

## Частые проблемы и решения

**Товар не появился на складе после «Получено / На складе».**
Проверьте, что стадия отмечена в системе как «приёмная» (у неё галочка `is_stock_in`). Обычно это стадии **«Получено / На складе»** и **«Готово к продаже»**. Если сомневаетесь — обратитесь к разработчику.

**Сделка «Продано», но пары не списались.**
Убедитесь, что в блоке «Склад · что продаём» **выбран товар и указано кол-во**. Без этого списание не произойдёт.

**«Дуплекс кода маркировки».**
Такой код уже есть в системе. Проверьте, не сканировали ли вы этот код на другой позиции.

**Оператор не видит цены.**
Так и задумано — цены редактирует только руководитель. Оператор видит остатки и работает с приходом-расходом.

**Не открывается страница склада.**
Обновите жёстко (`Ctrl+F5`). Если проблема осталась — обратитесь к разработчику.

**Забыл пароль оператора.**
Руководитель → **Пользователи** → в строке оператора введите новый пароль → **Пароль**.

**ТСД сканирует, но ничего не происходит.**
- Убедитесь, что курсор стоит **в поле сканера** (клик по нему).
- Проверьте, что ТСД настроен эмулировать клавиатуру + Enter в конце (обычно это дефолт).
- Отсканируйте штрих-код артикула (`K-00001`) — если это работает, значит ТСД в порядке; вопрос был в поле ввода.
